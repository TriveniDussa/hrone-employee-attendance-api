# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Returns `{"status": "ok"}` unconditionally without checking if MongoDB is alive. | MongoDB down or unreachable, but `/health` returns 200 instead of 503. | Added `client.admin.command('ping')` inside a `try/except` block, returning 503 on database ping failure. |
| 2 | `ensure_indexes` / startup | No database indexes created on application startup. | All queries execute `COLLSCAN`, violating the `/admin/explain` requirement and allowing duplicate records. | Implemented idempotent index creation during startup lifecycle (`@asynccontextmanager` `lifespan`) for unique keys and query fields. |
| 3 | `EmployeeIn` | Missing OpenAPI schema validations: regex for `emp_code`, string length limits, email regex, and `shift_start != shift_end`. | Invalid employee codes, invalid emails, or equal shift start/end accepted with 201 instead of 422. | Replaced with `EmployeeCreate` using strict Pydantic v2 `Field` patterns, calendar date validator on `joined_on`, and `model_validator` rejecting identical shift times. |
| 4 | `create_employee` | Check-then-insert race condition (`find_one` then `insert_one`) without relying on database unique index. | Concurrent `POST /employees` with identical `emp_code` inserts duplicates or raises unhandled `DuplicateKeyError` (500). | Relied on MongoDB unique index on `emp_code`, caught PyMongo `DuplicateKeyError`, and returned HTTP 409. |
| 5 | `create_employee` | `created_at` set to naive `datetime.now()` and serialized as ISO datetime string rather than epoch milliseconds. | Schema violation: contract requires integer epoch milliseconds (`int64`). | Stored UTC BSON datetime in MongoDB and converted to integer epoch milliseconds in API response. |
| 6 | `list_employees` | Off-by-one pagination error: `skip = page * page_size`. For `page=1`, it skipped the first 20 records. | First page of employees returns records 21–40 instead of 1–20. | Corrected formula to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` | Total count ignores filter: `total = db.employees.count_documents({})`. | Filtering by department `Sales` still reported total company headcount. | Changed to `db.employees.count_documents(q)`. |
| 8 | `list_employees` | Missing sort order: returned records in natural/arbitrary MongoDB order. | Response not sorted as specified in contract. | Added `.sort("emp_code", 1)` to cursor. |
| 9 | `punch_in` | Missing employee check: if `emp_code` does not exist, `emp["shift_start"]` crashed with 500 `TypeError`. | Punching in for non-existent employee crashed with 500 instead of 404. | Added explicit check returning HTTP 404 if employee does not exist. |
| 10 | `punch_in` / `get_attendance_date` | Local time used for date attribution; failed to handle overnight shifts (R1). | Punching in at 01:10 IST for a 22:00–06:00 shift incorrectly assigned the current date rather than the previous shift start date. | Implemented R1 helper converting to IST, checking overnight condition (`shift_end <= shift_start`), and assigning date to previous day when IST time < `shift_end`. |
| 11 | `punch_in` | Timestamps not truncated to whole seconds (R1). | Milliseconds and sub-second precision persisted, causing discrepancies in derived calculations. | Truncated instants to whole seconds before storage, calculations, and responses. |
| 12 | `punch_in` | Check-then-insert race condition on `(emp_code, date)` allows duplicate records on concurrent requests. | Concurrent punch-ins for the same day fail requirement (one 201, rest 409). | Created compound unique index on `{"emp_code": 1, "date": 1}`, caught `DuplicateKeyError`, and returned HTTP 409. |
| 13 | `punch_in` | Response injected internal MongoDB `"id": str(res.inserted_id)` and exposed raw datetimes. | Response violated contract: `_id` / `id` must never be exposed, and instants must be epoch milliseconds. | Stripped internal IDs and serialized `punch_in` as epoch milliseconds with required default derived fields. |
| 14 | `compute_late_minutes` | Threshold and timezone bug: `minutes = int((punch_in - start).total_seconds() / 60); return minutes if minutes > 10 else 0`. | At 10m 30s elapsed, `minutes` was 10, returning 0 instead of 10. Also naive vs aware timezone mismatch. | Measured elapsed seconds against shift start in IST. If `elapsed_seconds > 600`, return `int(elapsed_seconds // 60)`. |
| 15 | `compute_work_hours` | Used Python's built-in `round()`, which applies banker's rounding (round half to even) instead of half-up (R4). | Half-way numbers (e.g. 4.495) rounded towards even numbers instead of half-up. | Used Python `Decimal` with `ROUND_HALF_UP` to two decimal places. |
| 16 | `list_attendance` | Loaded entire collection into Python memory (`list(db.attendance_logs.find(q))`) and sorted in Python. | Performance bottleneck / out of memory on 100k records; violated contract. | Delegated sorting and pagination directly to MongoDB: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` and `count_documents(q)`. |

Also note anything you looked at and decided was **not** a defect, and why:

1. **Storing dates as plain `"YYYY-MM-DD"` strings:** Calendar dates are intentionally stored as ISO strings rather than BSON datetimes to avoid timezone shifts and keep dates pure calendar representations per `DATA_MODEL.md`.
2. **Omitting `_id` in API responses:** The contract specifies that `_id` is purely internal to MongoDB and must never appear in API requests or responses; records are addressed by business keys (`emp_code`, `date`).
